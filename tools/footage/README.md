# Test footage

Real court clips that every vision ticket (court mapping, corner auto-suggest, calibration, saved courts) is measured against. The clips are too big for git, so they live in a shared folder. Their manifest and hand-marked ground truth are kept here in the repo.

## Where things live

| What | Where |
|---|---|
| Clips (`.mov` / `.mp4`, 1080p60) | iCloud Drive folder `Chair Footage` (`~/Library/Mobile Documents/com~apple~CloudDocs/Chair Footage`) |
| Local copy the tests read | `~/chair-footage/` |
| Clip list | `tools/footage/manifest.json` |
| Ground truth, one file per clip | `tools/footage/ground_truth/<clip id>.json` |
| Synthetic fixture (2 s rendered court, used by unit tests) | `ios/Packages/ChairKit/Tests/ChairKitTests/Fixtures/Footage/`, regenerated by `python3 tools/footage/make_synthetic.py` |

## Commands

```sh
make footage        # copy the clips from the shared folder into ~/chair-footage
make test-footage   # run FootageTests against them; fails if ~/chair-footage is missing
make test           # FootageTests skip when ~/chair-footage is missing, so a fresh clone stays green
```

Both folders are make variables, so another machine can point somewhere else:

```sh
make footage FOOTAGE_SOURCE=/Volumes/Shared/Chair\ Footage FOOTAGE_DIR=/tmp/chair-footage
make test-footage FOOTAGE_DIR=/tmp/chair-footage
```

If iCloud has offloaded a clip, open the folder in Finder and choose Download Now before running `make footage`.

## Recording guide

For whoever films. One clip per setup.

- Note the phone model in the manifest's `device` field.
- 1× lens, never 0.5×. If both baselines don't fit, step back.
- 1080p at 60 fps. Lock exposure (long-press on the court in the Camera app until AE/AF LOCK shows).
- Landscape, phone 1–1.5 m off the ground, both baselines fully in frame.
- 30–120 s per clip, with play in it.
- Take a photo of the phone mount for each setup and keep it next to the clip in the shared folder (`<clip id>.jpg`).

The set needs:

- 8–12 net-post clips on at least two courts (hard, and clay or grass), covering bright sun, overcast and evening light, with both singles and doubles.
- 2 clips from the baseline placement and 1 from an umpire chair.
- One court filmed twice from the net post: once at the normal spot and once 1 m further back.

## Adding a clip

1. Name it `<court>-<placement>-<light>-<n>`, for example `riverside-netPost-overcast-1.mov`, and upload it to the shared folder.
2. Add an entry to `manifest.json`:

   ```json
   {
     "id": "riverside-netPost-overcast-1",
     "file": "riverside-netPost-overcast-1.mov",
     "court": "Riverside 3",
     "surface": "hard",
     "placement": "netPost",
     "light": "overcast",
     "duration": 94.5,
     "frameRate": 60,
     "device": "iPhone 13"
   }
   ```

   `surface` is `hard`, `clay` or `grass`; `placement` is `netPost`, `baseline` or `chair`; `light` is `bright`, `overcast` or `evening`. `duration` is in seconds.

3. Hand-mark `ground_truth/<clip id>.json`. Pixel coordinates are in the clip's own frame, with the origin at the top-left. Court coordinates are in metres, with the origin at the centre of the net, x along the net (−5.485 to +5.485), and y along the court (−11.885 to +11.885, positive towards the far end).

   ```json
   {
     "clip": "riverside-netPost-overcast-1",
     "frameSize": { "width": 1920, "height": 1080 },
     "corners": [
       { "frame": 0, "points": [ { "x": 412, "y": 288 }, { "x": 1530, "y": 301 }, { "x": 1802, "y": 940 }, { "x": 96, "y": 902 } ] },
       { "frame": 600, "points": [ ... ] }
     ],
     "groundPoints": [
       { "name": "far service line, centre service line", "pixel": { "x": 960, "y": 455 }, "court": { "x": 0, "y": 6.4 } }
     ]
   }
   ```

   - `corners`: the four outer doubles corners at frame 0 and every 600 frames after that, ordered far-left, far-right, near-right, near-left. That order runs clockwise on screen.
   - `groundPoints`: at least 10 line intersections, each with its pixel and court position. Use the centre of the painted lines.

4. Run `make footage && make test-footage`. The consistency test names anything that doesn't add up: a missing file, a missing corner frame, corners out of order, too few ground points, or a point off the court.
